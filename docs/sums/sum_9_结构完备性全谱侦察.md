**L4 滚动重估适用域（数据裁决）**：滚动 336h 模板对价格**无增益**
（P0 1.27% vs P1 2.89%——价格 t=1245 变点后冻结段回升非单调，滚动跟随过时低水平）；
适用域=单调漂移序列（任务侧 B10 已有 / NonAI 由 L1 覆盖）——方法学教训。
**误报澄清**：滚动模板初版 25.2% 曾疑似"PricePeriod 标签映射时域漂移"
（窗口 hod 4-6 预测成 Flat 水平）——数据核查全部段 hod→label 映射一致，
真因是 rolling hod 键错位 bug（#39：len(seg)%24 假设窗口从 hod 0 起，
实际窗口起点 2044%24=4 → 键平移 4h），修复后 25.2%→2.89%；
**教训：单点对比推断结构变化前，先排除自身实现错误（三关纪律·口径干净）**。

**性能诊断（竞技榜慢源）**：deep `_predict_roll` 逐点 GPU 前向 + 每次 fit/predict
重建网络 + 每 epoch 全量验证 → 每序列 ~20s（占全量 55 分钟大头）；
GPU 95-99% 持续占用可能触发笔记本功耗墙降频（标定 37.9s → 实际 79s/序列的
2 倍退化）——perf 优化（预测 GPU 化/网络复用）后 deep 每序列 0.8-3.8s（3-7 倍）。
**计时结构复核**：perf 后全量仍 ~55 分钟——实测 CV 阶段 26 分钟 + **融合阶段
~28 分钟（52%）为主耗时**（fuse_energy 每序列重训全部入选模型 5 折 + 全段，
含 TabPFN/deep 重复 fit）；deep 优化价值在 CV 段（7%）与 GPU 满载时长。
已知留待：融合 OOF 复用 CV 结果（改动大，M6 可选）。
**perf 验收教训**：perf 后全量重跑发现 deep 维度 bug（#41，energy 126→108 假象）
与 seed 缺失（#42）——单序列测试通过≠全量通过，perf 改动以竞技榜全量重跑为准；
修复后 energy 126/192 恢复、两次运行逐位一致（可复现）。
