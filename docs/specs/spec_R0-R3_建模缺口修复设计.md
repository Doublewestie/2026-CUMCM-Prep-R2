## D-R1 消纳口径：常数 c_r → c_r(h) 日内模板

- **背景**：评估器 U = min(W, c_r·D)（c_r = U/D 中位数），D/F 区命中率仅 8-24%
- **实证**：U/D 对每个小时跨天完全恒定（六区 max std = 0.000000）→ 生成规则
  U = c_r(h)·D；与 W 无关（corr(残差,W)≈0，min 形式不存在——W 从未成为瓶颈）
- **决策**：fit_consume_ratio 拟合 24 值日内模板 + 正弦参数化（论文素材）；
  evaluate_schedule 模板口径（主时段 U=c_r(h)·D；Closure 段 U=min(W,D)）；
  优化场景保留全覆盖口径（U=min(W,D)）
- **备选**：保持 min(W,cD) 并声明"主模式校准"（被否：形式错误被包装成数据局限）
- **验证**：六区模板命中率 1.0；基线向题目锚点收敛（NU 31.15→32.07%、
  弃电 795→784.7 万 MWh）；E1 结论稳健（a5 敏感性 ±10% 全 <0.5pp）
- **形状发现**：A/B/C 共享归一化形状（基准等差 0.12/0.15/0.18）；D/F 完美单正弦
  （R²=1.0000，相位全域一致）；E 平台 0.55 + 白天对称钟形（峰 0.73@12h）

## D-R0 校准段修复：2352-2375 决策、2376-2399 纯验证

- **背景**：step1.2 注释声称"真实校准 2352-2375"，但 SEG_CAL=2376 →
  `arange(2376,2400)` 实际在冻结段选 ε（三段协议破坏，冻结段被污染）
- **实证**：正确口径 2352-2375 上伪校准 0.939 vs 真校准 0.938（差 0.2pp）；
  sum_2 的"漂移 6.4pp"（0.939 vs 0.875）是冻结段段间差异被误读
- **决策**：SEG_CAL_START=2352 / SEG_CAL_END=2376；calibration_fix 字段记录修正
- **验证**：重跑后 ε=0.05 仍入选（2352-2375 cov=0.979），E1 gap 不变；
  冻结段回归纯验证（step1.7 S4 超容率 4.86%≈ε=5% 设计）
- **教训**：校准窗与参考窗须对称；注释与实现不一致是协议级 bug 温床

## D-R3 SOC 口径：效率分区制 + 递推重建

- **背景**：早期文档"充放效率 0.93/0.92 全区域"（storage 表实际为分区制）；
  RegionE SOC(0) 数据表与递推差 ~1MWh（主办方确认录入误差，建议以公式重算）
- **实证**：分区效率（A/B/C 0.93/0.92；D/E/F 0.94/0.93）递推与数据表完全吻合
  （A/B/C/D/F mean|diff|≤0.002，数据表=round(递推,3位)）；RegionE 全程偏移 −1.0
  （不止 hour0）；D/E/F 基线 SOC(2406) < InitialSOC（Q3 终态约束张力）
- **决策**：CONSTITUTION/PLAN_details 修正为分区制；step0.5_soc_rebuild.py
  递推重建（Q3 输入 = soc_rebuilt.csv）；官方推荐措辞声明
- **验证**：6 项测试（递推吻合/偏移标记/界内/终态特征）；数据表本身恒在界内

## D-R2 冻结段职责：生成器收尾结构（非 24h 噪声）

- **背景**：冻结段 CV-最优一致率 8.3% 曾被归因"24h 短窗噪声"
- **实证**：需求水平抬升 +20%（GPU-hour 2499 vs 2089），z=2.86/100 百分位；
  覆盖率条件于需求水平（高需求窗低 1.8pp）；常数分位数 0.917 → 滚动 336h 0.944
- **决策**：冻结段职责 = 最终验证（κ_ε 兑现/覆盖率/绝对质量），不承担排名裁决；
  滚动重估作为外推失效的建模修复（nowcast，shift≥1 防泄漏）
- **验证**：step1.7 S1-S5 全落盘 + 5 项测试；价格 0.19% 之谜解开
  （日模板 1.27% < 段标签均值 2.48%，残差修正命中段内结构）
